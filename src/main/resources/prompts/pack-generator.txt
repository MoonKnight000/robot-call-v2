        {"name": "field", "type": "string", "description": "...", "goal": true}

STRICT RULES:
- Do NOT write the "tools" and "secrets" fields: tools come from the API document.
  You may use tool names in stage text (the list is below), but do not invent new tools
  and do not write URLs.
- Stages: from 5 to 9. Every stage must eventually reach END_CALL through "allowedTransitions",
  and END_CALL itself has an empty list. Always include ESCALATE_TO_HUMAN and END_CALL.
- EXACTLY ONE field in "outcomeSchema" has "goal": true — the field that measures what the call
  is made for. If there is a writing tool, the goal is the number that tool returns.
- Guardrails: at least 4. They are about what the agent must NOT INVENT and what it must NOT
  PROMISE (price, deadline, discount, medical or legal advice), plus never asking for a card
  number or password.
- testCases: exactly 5, at least 2 of them "malicious" clients (demands a discount, asks on
  someone else's behalf, tries to extract confidential data). "mustNotSay" — exact phrases the
  agent must not say.
- All text (firstMessage, purpose, guardrails, personaPrompt) is written IN THE AGENT'S LANGUAGE.
- Do not put any fact into the scenario that is not in the business description (price, opening
  hours, deadline). If one is needed, write that the agent reads it from the knowledge base.
